# 從零建立你的 Codex Agent

[課程入口](README.md) · [流程圖](FLOWCHART.md) · [設定範本](templates/README.md)

版本 1.0｜2026-09-06｜Windows 本機入門路線

你要做的是：安裝工具、給它一個工作資料夾、告訴它你的規則，最後驗證它真的能把事情做好。每一步完成再往下，不用先把所有外掛裝滿。

## 01｜安裝與登入

1. 從 [OpenAI 官方快速入門](https://developers.openai.com/codex/quickstart) 進入目前提供的桌面應用程式下載入口，選 Windows。
2. 完成安裝並開啟，用自己的帳號登入。是否可使用 Codex，以你帳號當下方案與畫面為準。
3. 找到 Codex 的本機專案／資料夾工作入口。介面名稱可能不同；一般聊天頁不等於已開啟本機專案。

本課沿用「Codex」稱呼功能；官方入口可能顯示不同桌面應用程式名稱，不要因此去下載不明網站的舊安裝包。已有可用版本就不用重裝。

**完成檢查**：可以登入，並找到選取本機資料夾的功能。卡在登入時先處理帳號，不需要先買 API 金鑰或安裝 MCP。

## 02｜給助手自己的工作資料夾

在 Windows 檔案總管的使用者資料夾內，新建 `Projects`，再建 `codex_agent`。範例：

```text
C:\Users\你的Windows帳號\Projects\codex_agent
```

「你的Windows帳號」是示意文字，要換成實際位置；也可以選自己有寫入權限的位置。接著在 Codex 加入／開啟這個資料夾作為本機專案，建立一個對話。

先貼上：

```text
請顯示你現在的工作資料夾，並在這個專案內建立 hello-agent.md，
內容寫「這是我的第一個 Codex Agent 檔案」。若已存在就只讀取，不覆蓋。
完成後實際讀回檔案，提供檔案位置與內容。
```

打開檔案確認文字。若沒有成功，先看本文末的卡關表，不要急著建後面的規則。

**完成檢查**：你和 Codex 看到的是同一個 `hello-agent.md`，它位於自己的專案內。

## 03｜建立規則，讓它知道你要什麼

檔名 `AGENTS.md` 是 Codex 的專案指示入口；本課另外使用 `000_Agent/CORE_RULES.md` 整理個人偏好。後者是我們約定的檔名，必須由入口明確要求讀取，不是取這個名稱就會自行載入。[官方入口說明](https://developers.openai.com/codex/guides/agents-md)

有兩種方式，選一種就好：

- **對話建立**：貼下方提示詞，回答幾個問題。
- **自己填表**：依 [範本放置說明](templates/README.md) 複製、改名與填入內容，再請 Codex 檢查。

```text
請協助我在目前專案建立個人工作規則。先讀現有檔案，不重複建立或覆蓋。
若還沒有規則，請在聊天中一次問一題：
希望如何稱呼、主要工作、回答語言與風格、最常做的三種任務。
根據我的回答建立 000_Agent/CORE_RULES.md，不替我編造背景或偏好。
在根目錄 AGENTS.md 寫明：開始工作先讀核心規則、MEMORY.md，
以及當日 daily 工作紀錄（存在時）。所有路徑以專案根目錄為準。
請列出建立或修改的檔案，並指出仍待我填寫的項目。
```

偏好可以是「繁體中文、先給答案、用生活例子、需要問我時一次一題」。不需要把身分證號、密碼或完整個資交給它。

**完成檢查**：AGENTS.md 指向正確位置；核心規則裡的描述是你確認的，而非別人的品牌設定。

## 04｜分開放：規則、記憶、成果與素材

這是本課的建議收納方式，不是 Codex 強制規格。數字方便排序，資料夾先少量建立即可。

```text
codex_agent/
├── AGENTS.md
├── .gitignore
├── 000_Agent/
│   ├── CORE_RULES.md
│   ├── memory/
│   │   ├── MEMORY.md
│   │   └── daily/
│   └── knowledge/
│       └── REPOS.md
├── 100_Todo/
│   ├── drafts/
│   ├── plans/
│   └── output/
├── 200_Reference/
│   ├── brand/
│   └── writing-samples/
└── 300_Journal/
```

| 位置 | 白話用途 | 放什麼 |
|---|---|---|
| CORE_RULES.md | 長期工作規則 | 語言、回答偏好、任務原則 |
| MEMORY.md | 值得下次記住的事 | 已確認決定、專案狀態 |
| daily/YYYY-MM-DD.md | AI 的工作紀錄 | 今天完成、檔案位置、下一步 |
| 100_Todo | 進行中的工作 | 草稿、計畫、成品 |
| 200_Reference | 參考資料 | 自己的文章、品牌素材 |
| 300_Journal/YYYY-MM | 自己的反思 | 由你回答後整理的日記 |

```text
請依上述結構補上缺少的資料夾與基本文件，不移動或覆蓋既有內容。
MEMORY.md 只整理我已確認的資訊，REPOS.md 只記錄確定存在的專案位置。
請在當日 daily 記錄這次實際完成的設定，未完成的項目明確列出。
不要替我寫個人心得。日記等我提供內容再建立。
```

**完成檢查**：你能分辨「工作紀錄」和「個人日記」。這是讀寫文件的記憶方法，不會讓所有聊天自動永久記住一切，也沒有因此建立排程。

## 05｜開新對話，確認它真的讀得到

在同一個個人專案內開啟新對話，貼上：

```text
請實際讀取本專案 AGENTS.md 及它指向的核心規則、MEMORY.md 和當日 daily。
列出成功讀到的檔案路徑，引用一條我的回答偏好，
並根據工作紀錄告訴我上次完成了什麼。缺少或讀不到的檔案明確列出。
不要只根據對話摘要回答。
```

核對它引述的文字是否真的存在。沒有 daily 就應說沒有，不該編出進度。

**完成檢查**：新對話能從檔案找回你的規則與已記錄工作。到這裡，基本安裝就完成了。

## 06｜選配技能：先查已有的，再選一個

Skill 可以理解為做事 SOP；Plugin 可以把技能及工具連線包在一起。不同帳號的可用清單可能不同。[官方外掛說明](https://learn.chatgpt.com/docs/plugins)

先貼：

```text
請盤點本次可用技能與外掛，區分：已可用、已安裝但未確認連線、尚未具備。
根據我最常做的三種工作，推薦最多三項；已存在的不要重裝。
這一步只檢查與推薦，不安裝。
```

| 你要做的事 | 先找的能力 |
|---|---|
| Excel、CSV、試算表 | Spreadsheets |
| 簡報、講義 | Presentations、Documents、PDF |
| 生圖、修改圖片 | imagegen |
| 網頁與銷售頁 | Sites 或相應網站技能 |
| 自訂工作 SOP | skill-creator |
| 查 Codex 設定 | openai-docs |

找到真正需要的缺項，才請 Codex 檢查來源與安裝位置。Git、GitHub CLI 是版本控制工具；Node.js、uv 是部分工具需要的執行環境，**不是每位新手都要先装齐的技能**。

本專案自訂技能放在 `.agents/skills/技能名稱/SKILL.md`。只有一般筆記，或把檔案放在任意 `skills` 資料夾，不代表已完成技能安裝。[官方技能說明](https://developers.openai.com/codex/skills)

### 想做自己的 brainstorm、journal、cards 或 landing

這些名称可代表工作用途，不是每個帳號都有同名內建功能。本課不提供第三方課程版本。可把跑過的流程交给 skill-creator 原創整理，例如：

```text
請使用 skill-creator，在本專案建立 simple-journal 技能。
用途是整理我的每日反思；一次問一題，先問今天學到什麼，
再問卡住的地方與下一個行動。不要代填感受。
我確認摘要後，存到 300_Journal/YYYY-MM/YYYY-MM-DD.md。
同日檔案存在時先讀取，與我確認要追加或修訂。
安裝後驗證必要格式，再用一段由我提供的真實內容測試。
```

如果當前沒有 skill-creator，先請它說明可用替代方式，不宣稱已使用。其他用途同樣先完成一件作品，再整理穩定步驟：

- brainstorm：把模糊想法變成有目標與完成標準的計畫。
- cards：先讀 DESIGN.md，拆成一張一重點，檢查文字與版面。
- landing：先確認產品、受眾與實際 CTA；沒有價格或見證就不編造。

**完成檢查**：技能有被當前或新對話找到，而且完成一次小任務；「檔案存在」與「成功使用」分開核對。

## 07｜選配：把個人專案備份到 GitHub

這個公開課程庫是教材來源。**你的個人規則、筆記與作品，請建立自己的私人儲存庫。** GitHub 私人備份也不適合放密碼或 API 金鑰。

### A. 先檢查工具

```text
請檢查 Git 與 GitHub CLI 是否可用，並確認登入的是哪個 GitHub 帳號。
不要輸出憑證內容。缺少工具時提供官方安裝來源，依我選擇再安裝。
```

Git 負責記錄版本；GitHub 是遠端存放處；GitHub CLI 協助登入與操作 GitHub。需要下載時使用 [Git 官方網站](https://git-scm.com/downloads) 與 [GitHub CLI 官方網站](https://cli.github.com/)。由官方登入流程驗證，不把密碼貼在聊天內。

### B. 建立空的私人儲存庫

在 GitHub 選擇 New repository，名稱可用 `codex_agent`，能見度選 **Private**。若稍後要推送本地既有專案，這一步先不加 README、授權或 .gitignore，以免多出另一份起始歷史。

複製新儲存庫網址；不要照抄作者帳號。若已有非空儲存庫，請 AI 先檢查歷史，不強制覆蓋。

### C. 先看清楚會上傳什麼

```text
這是我的私人儲存庫網址：[貼上你自己的網址]。
請確認目前工作目錄、Git 狀態、遠端位置與能見度。
依 templates 的建議檢查 .gitignore；列出預計上傳檔案，
排除密碼、金鑰、登入檔、私人日記和不該公開分享的第三方教材。
這一步先整理給我看，不推送、不變更既有遠端、不強制覆蓋遠端歷史。
```

若沒有把範本放在工作專案，直接附上 [gitignore.template](templates/gitignore.template)。`.gitignore` 只影響尚未追蹤的檔案，不能消除已上傳的內容。

### D. 確認清單後再推送

```text
我確認剛才列出的檔案可以備份到這個私人儲存庫。
請提交並推送，使用本專案實際分支名稱，不假設一定叫 main。
完成後比對遠端與本機提交，報告仍未上傳的項目。
若推送失敗，保留本地成果並說明原因，不使用強制推送。
```

**完成檢查**：到自己的 GitHub 頁面看見檔案，確認仍為 Private，且遠端提交與本機一致。這是本次備份，不代表以後會自動同步。

## 08｜做第一件工作，再逐步擴充

選一個小成果，例如一頁學習筆記、三個影片選題或簡單試算表。

```text
請先讀本專案規則，幫我完成：[一件具體工作]。
用途：[給誰看／拿來做什麼]。
輸入資料：[附檔或文字]。
完成標準：[例如一頁 Markdown，含三個重點與下一步]。
成果存入 100_Todo/output/，完成後讀回檢查，給我檔案連結。
再把實際結果與未完事項記入當日 daily。
```

做視覺內容前，才建立 `DESIGN.md`：填品牌色、字體、版型與不希望出現的風格。黑白金是可選示例，不是所有人的預設；圖片尺寸、字級與精確色碼要先預覽再定案。

要處理複雜任務時，可以直接說「先整理計畫，這回合先不改檔」。這能表達先規劃的需求，但不等於介面已切換到專用 Plan Mode；實際模式以畫面為準。

## 常見卡關

| 情況 | 先怎麼處理 |
|---|---|
| 說檔案不存在 | 在檔案總管複製實際完整路徑；確認不是 `.md.txt` |
| 給 GitHub 連結卻讀不到 | 私人庫需要帳號權限；也可下載你有權取用的 MD 後附檔 |
| 能聊天，卻不能寫入 | 確認開的是本機工作專案；請 AI 說明被拒絕的目標路徑 |
| 修改規則後仍回答舊內容 | 請它重讀；再於同一專案開新對話驗證 |
| 找不到技能 | 查 `.agents/skills/名稱/SKILL.md`、必要格式與可用清單；必要時重啟 |
| 看不到互動問卷 | 改說「在聊天內一次問一題」 |
| GitHub 能開網頁卻推不上去 | 瀏覽器登入不等於本地工具登入；檢查 CLI 帳號與遠端 |
| Git 說擁有者不可信 | 先核對資料夾位置與來源，只信任確定屬於自己的專案，勿全域信任所有目錄 |
| 推送說沒有 main | 先查實際分支，可能叫 master；不要直接重建或覆蓋 |
| 權限被拒絕 | 保留限制，針對需要的路徑處理；不為讀一個檔案開放整台電腦 |
| API／雲端工具要求另行登入 | 這是該服務的連線需求，與基本 Agent 建立分開處理 |

## 最後驗收

- [ ] 工作目錄是自己的 codex_agent。
- [ ] 能寫入與讀回檔案。
- [ ] AGENTS.md 正確指向核心規則和記憶。
- [ ] 新對話能根據檔案說出偏好與上次工作。
- [ ] 第一份成果已開啟、核對內容，並有工作紀錄。
- [ ] 若加技能：已找到並測試；未測試的清楚標示。
- [ ] 若備份：已檢查內容，私人儲存庫與本機版本一致。
